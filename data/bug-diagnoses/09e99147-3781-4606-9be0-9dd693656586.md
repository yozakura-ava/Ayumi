```
This is a **class attribute**, so every `KillSwitchManager()` instance starts administratively disabled. All `activate_global_kill` / `activate_global_freeze` calls short-circuit with `INFO | kill_switch | activate_global_kill suppressed (kill switch disabled): reason=...` and `is_active()` always returns False.

**Impact:** Harness-wired FTMOGuard (child 1 fix, merged ac2e959e) and RiskGuard both call into the kill switch, but those calls are no-ops. Evidence: `reports/blend-harness-2026-09-07/blend_xauusd_postfix.json` shows `net_pnl=-123700.35`, `final_balance=-113700.35`, `bars_processed=342`. `harness_wide_killed.log:2026-09-07 20:33:45` records:

INFO | kill_switch | activate_global_kill suppressed (kill switch disabled): reason=ftmo_daily_loss_limit by=risk_guard
```
Guard fired; halt was suppressed.

**Production concern:** Card explicitly says "DO NOT silently flip defaults in the production launcher path — live semantics are Craig-gated." So the class default `_disabled = True` MUST stay as the production launcher default. The fix must give the harness an explicit enable without flipping production.

## Root Cause

**Category:** State error (administrative class-level flag suppresses all activations silently).

**One-sentence root cause:** `KillSwitchManager._disabled = True` is hardcoded as a class attribute with no log line, no constructor override, and no harness-specific enable, so all `activate_global_*` calls are silently suppressed and `is_active()` always reports False — exactly the failure mode that let the harness drain -$123K on parent card 76046374's re-run.

## Analysis

**Call path:**
1. `scripts/backtest_blend_harness.py:395` constructs `FTMOGuard(kill_switch=engine._kill_switch, …)`.
2. `engine._kill_switch = KillSwitchManager()` is created in `src/forex_bot/adapters/ctrader/forward_test_engine.py:535` — no constructor args, inherits class default `_disabled=True`.
3. Each bar: `_ftmo_guard.update(balance, open_n)` runs FTMO logic. On breach, it calls `self._kill_switch.activate_global_kill(reason=…)` (`src/forex_bot/risk/ftmo_guard.py:635`).
4. `activate_global_kill` (`src/forex_bot/adapters/ctrader/kill_switch.py:223`): `if self._disabled: logger.info("activate_global_kill suppressed…"); return`. Activation is a no-op.
5. `engine._running` is never flipped to False. Eval loop runs to completion with no halt.

**Why safeguards didn't catch it:**
- The "STARTUP: Kill switch CLEAR — enforcement active" log at `forward_test_engine.py:541` is misleading — it reads `is_globally_killed()` which returns `False` precisely *because* `_disabled=True` (line 174 short-circuit). The log fires green even when the kill switch is non-functional.
- The existing test fixture in `tests/unit/risk/test_kill_switch.py:25` (`_enable_kill_switch_for_tests`) flips `KillSwitchManager._disabled = False` for the test class, masking the production-disabled default from the test suite.
- No runtime check exists that asserts "kill switch activations are not suppressed" at startup. The startup log said "CLEAR — enforcement active" while enforcement was actually disabled.

## Fix Strategy

- **Scope:** 3 files (within ≤4 cap):
  1. `src/forex_bot/adapters/ctrader/kill_switch.py` — add `disabled: bool | None = None` constructor param + loud startup log.
  2. `scripts/backtest_blend_harness.py` — flip `KillSwitchManager._disabled = False`, log loud harness override, recreate engine's kill switch instance.
  3. `tests/unit/risk/test_kill_switch_enable_harness.py` (new) — 9 cases covering constructor override, harness halt-on-breach, startup log lines, and mock-pattern backward compatibility.
- **Approach:** Keep `_disabled = True` as the production safety default (Craig directive, Jun 27). Allow explicit per-instance override via constructor; loud WARNING-level log at every `__init__` makes the choice unmissable. Harness explicitly enables via class flip before re-constructing the engine's kill switch instance.
- **Side effects:** None on production launcher (default path unchanged behaviorally; new loud log is additive). Backward compatible with existing `test_kill_switch.py` fixture (class attribute flip pattern preserved).
- **Test plan:** `python3 -m pytest tests/unit/risk/test_kill_switch_enable_harness.py -v` (direct pytest per card spec, not `run_test_scope.sh`).
- **Alternatives considered:**
  - Flip class default to `False`: rejected — silently changes production semantics, contradicts card directive.
  - Read env var `AYUMI_KILLSWITCH_ENABLED`: rejected — adds a runtime config surface; harness already has explicit control via class flip.
  - Add `enable()` method only, no constructor arg: rejected — constructor arg is more explicit and standard.
