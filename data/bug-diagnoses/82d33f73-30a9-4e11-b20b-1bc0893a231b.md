## Triage
The tournament CLI exits non-zero on the host when no signals are produced (c4b86732 fail-loud guard) but exits 0 on the node with `TOURNAMENT_OK rows=0`. The divergence has a single root cause: a **dual silent-empty path** — the harness raises `TournamentNoSignals` for one class of empty (signal-emit failure) and `continue`s through an `except Exception` for another class (strategy-import failure). Both produce zero rows in the scorecard, but only the first raises.

This is exactly Kaito's hypothesis: "node 'TOURNAMENT_OK rows=0' is the silent-empty path (strategy import failure -> except Exception skip -> no rows, exit 0); host raises because imports work." Confirmed by:
- Host smoke: `srmr_plus` imports successfully → harness raises `TournamentNoSignals` (0 signals) → CLI catches as `TournamentEmptyWindow` → exit 1, ERROR printed.
- Node smoke: at least one strategy's import throws (env mismatch) → loop `continue`s with `run_meta[strategy_id]["skipped"]=True` → no row → CLI proceeds to `TOURNAMENT_OK rows=0` → exit 0.

Both behaviors emit a scorecard with zero rows; the host fails loud, the node stays silent. The skill `ayumi-tournament-run` §Node execution (verified 2026-09-20) already calls this out as a known-limit: "host build instead raises TournamentNoSignals on the USDJPY smoke window — fail-loud guard vs smoke config conflict, still unfixed."

## Root Cause
**Category: state error (dual silent-empty path)** — the harness has two ways to produce an empty scorecard (import-error swallowed by `except Exception`; signal-empty raised as `TournamentNoSignals`). The CLI's `TOURNAMENT_OK rows=0` summary fires regardless, masking the divergence.

One sentence root cause: **the harness enforces fail-loud only for one of two empty code paths; the CLI emits the `TOURNAMENT_OK` summary before checking whether any row was produced.**

## Analysis
- `src/tournament/harness.py` line ~887: when `bars_processed == 0 or len(signals) == 0`, the harness **raises** `TournamentNoSignals`. This BLOCKS the rest of the strategies in the loop (because the exception propagates out of `run()`), and propagates to the CLI which prints ERROR and exits 1.
- `src/tournament/harness.py` line ~880: when `_extract_signals_from_strategy` raises (strategy import failure, missing config, etc.), the loop catches via `except Exception` and **silently skips** that strategy with `run_meta[sid]["skipped"]=True`. The loop continues; if this was the only failing strategy OR every strategy ends up skipped, the scorecard is empty BUT no exception fires.
- `scripts/run_tournament.py` line ~185: the CLI prints `TOURNAMENT_OK rows={len(scorecard.rows)}` UNCONDITIONALLY (regardless of whether rows is zero) and returns 0 unconditionally when no exception propagated.

The node-vs-host divergence is therefore:
- Host: strategy import succeeds → reaches signal-empty guard → raises → CLI exits 1 → operator sees ERROR.
- Node: import fails (env mismatch) → caught silently → loop continues → all rows empty → no exception → CLI prints `TOURNAMENT_OK rows=0` → exits 0 → operator thinks it passed.

This is a SAFETY-RELEVANT divergence: a strategy that silently dies because of an env mismatch on the node WILL not surface as a failure to the operator, masking a real bug.

The matrix runner (`scripts/offload/worker_runner.py`) already has per-cell handling: it catches `TournamentNoSignals` (exit_code=3), `TournamentEmptyWindow` (exit_code=2), and `if not scorecard.rows` (exit_code=4). It also has the right per-cell "skip-and-continue" semantic. The bug is purely in the **single-run CLI** path.

## Fix Strategy

### Scope
- `src/tournament/harness.py` (~10 lines in `run()` — convert raise to skip-and-continue for per-strategy signal-empty; emit `signals_skipped=True` in `run_meta`)
- `scripts/run_tournament.py` (~5 lines — add `if not scorecard.rows: return 1` after the try/except, before the summary; also change `--smoke` default window from USDJPY to XAUUSD H1 with a wider window so smoke produces ≥1 signal)
- `tests/test_tournament_empty_window.py` (~30 lines — update for new skip-and-continue contract; add test for `if not scorecard.rows: return 1`)

### Approach
1. **Harness: skip-and-continue (no break) on per-strategy signal-empty.** Mark the strategy as `signals_skipped=True` in `run_meta` with the strategy/symbol/window context in `error`. Loop continues; subsequent strategies still execute. The scorecard ends up with 0 rows if every strategy was either skipped or signal-empty. Keep the `TournamentNoSignals` exception class as a documented construct (used by callers that want to format a specific error message), but never raise it from `harness.run()` per-strategy. This satisfies council binding #3: "tolerate per-cell TournamentNoSignals from warm-up/indicator mismatch as skip-and-continue".
2. **CLI: single source of truth for the silent-empty exit.** After the try/except block, check `if not scorecard.rows: print(FATAL ...); return 1`. Do this regardless of whether `TournamentEmptyWindow` was raised (which is now only for actual 0-bars-in-window cases). This satisfies council binding #1 (Kaito): "CLI exits non-zero when scorecard has no rows ('if not scorecard.rows: return 1') so silent-empty fails loud on BOTH surfaces".
3. **Smoke default: use XAUUSD H1 with a wider deterministic window** that emits ≥1 signal in 2×4 strategies. Change `_default_smoke_window` to a fixed range on XAUUSD (label is `xauusd-only`). Keep the window deterministic (hardcoded) so re-runs are reproducible. Document the change in the smoke docstring. This satisfies AC3: "ends with `TOURNAMENT_OK` on both host and node".
4. **Worker runner: keep per-cell semantics, add the same `no_scorecard_rows` guard for the matrix exit_code=4 path** (already exists, line ~290).
5. **Deterministic parity fixture (council binding #2 / Sora hard gate):**
   - Single-strategy, single-TF, frozen-window synthetic DuckDB at `data/tournament/parity_fixture.duckdb` (3 strategies × 1 TF × fixed 30-day window from 2024-01-01 → 2024-01-31).
   - SHA-256 hash of the fixture file embedded in the scorecard meta (`fixture_sha256`) for byte-identical detection.
   - Run the harness on host and on node, dump JSON scorecard, diff byte-by-byte. Document any diff.

### Side Effects
- `scripts/offload/worker_runner.py` `except TournamentNoSignals` becomes a safety-net for direct harness calls outside the CLI. Still useful: returns exit_code=3 for callers that don't catch it.
- The smoke change (USDJPY → XAUUSD) affects callers that depend on `--smoke --symbol USDJPY` matching the default. Mitigation: the default `--symbol` arg stays `USDJPY` (since the test fixture uses USDJPY), but the `--smoke` flag overrides symbol AND window together so callers invoking `--smoke` get the new XAUUSD window. Document in the help string.

### Test Plan
- `tests/test_tournament_empty_window.py` — update to verify skip-and-continue (single strategy with 0 signals → scorecard has 0 rows, run_meta[sid]["signals_skipped"]=True, no exception).
- New: `tests/test_tournament_smoke_parity.py` — verify `if not scorecard.rows: return 1` (CLI exits 1 with FATAL message), and verify `--smoke` produces ≥1 row on the new XAUUSD window.
- New: `tests/test_parity_fixture.py` — verify the parity fixture is deterministic (same SHA-256 across runs), and that the harness output contains the fixture hash in meta.

### Alternatives Considered
- **Make `TournamentNoSignals` config-explicit (env var to disable).** Rejected: hides the bug. The skip-and-continue approach makes the silent path visible (run_meta) AND the loud path unified (CLI exit).
- **Skip fail-loud entirely.** Rejected: council binding requires fail-loud. The matrix can still get per-cell fail-loud via the worker_runner.
- **Larger smoke window on USDJPY.** Rejected: USDJPY H1 smoke-sized coverage is too thin (skill note). XAUUSD H1 has 2022-01 → present coverage; the wider window is more representative.
