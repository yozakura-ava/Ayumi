## Triage

Three co-located defects on the S1 eval/statistics path of the live forward-test:

1. **`data/signal_stats.jsonl` writer silence.** File mtime is `Aug 18 10:30` (505 lines total), no writes since. The forward-test process has been producing signals (B5 `signals=15` summed across evals #57–#88, Aug 19 12:15 → 20:00) but none have been recorded. Post-20:10Z Aug 19 restart eval count is #1–#3 with `signals=0` (still zero recorded).
2. **`last=1151359s` (~13.3d) bogus epoch at fresh start.** `_strategy_last_eval` is seeded `{s.name: 0.0}` at engine init but `time.monotonic()` clock is read at health-check time, so the first `last_eval_ago = monotonic() - 0.0 ≈ machine uptime`. Fix: seed from monotonic-at-init.
3. **Missing `ticks-flow-but-bars-static` watchdog.** `data/heartbeat_trading.json` carries `ticks_received` / `bars_built` but no `tps` / `bars_static_age_sec` field, so `scripts/daily_audit.py:SH-002` reads `tps_5min_avg → 0.0` and reports CRITICAL silent every audit. Detection of "ticks flow but no new bar for ≥20 min" does not exist (only the existing `total_bars == 0` startup-grace check exists at forward_test_engine.py:3168).

The card scope is S1 eval/statistics path only — no live-trading or signal-generation behavior changes.

## Root Cause

### Writer silence — **Category: integration / call-graph gap**

The forward-test deploys with `blend_mode=True` (`scripts/launch_blend_forward_test.py:1430`). Tracing the signal path:

```
ForwardTestEngine._evaluate_strategies() (scripts/launch_blend_forward_test.py:441)
  └─ BlendForwardTestEngine._route_signal()    (scripts/launch_blend_forward_test.py:575)
       └─ blend_runner.on_signal()             (src/forex_bot/forward_test/blend_runner.py:376)
            └─ SignalOrchestrator.process_signal()  (src/forex_bot/orchestrator/signal_orchestrator.py:61)
                 ↳ confidence + routing + sizing — NO stats recorder call
```

The `cTraderSignalAdapter.evaluate_and_trade()` shortcut at `src/forex_bot/adapters/ctrader/signal_adapter.py:206-208`:
```python
if self._blend_mode:
    # In blend mode, sizing and execution are handled by the blend runner.
    # Return the signal without executing through paper_trader.
    return trade_signal
```
explicitly **bypasses** `PaperTrader.process_signal()` — which is the only place that calls `SignalStatsRecorder.record_signal()` (`src/forex_bot/adapters/ctrader/paper_trader.py:231`). The downstream `_orchestrator.process_signal()` and `BlendForwardTestRunner.on_signal()` paths never touch `signal_stats.jsonl`. The JSONL writer is only invoked in the **non-blend** path (`PaperTrader.process_signal`) and the **live-trading** path (`_execute_signal_live` at forward_test_engine.py:1833 — only called when `cfg.live_mode=True`).

**This is not buffered-write tail loss.** `SignalStatsRecorder._append_line` (`signal_stats.py:308-353`) opens, writes, fsyncs, and `os.replace`s atomically per call. There is no persistent TextIOWrapper. The 22h+ silence is structural: no caller invokes `record_signal()` in blend mode.

### last= epoch init — **Category: state error**

`ForwardTestEngine.__init__` at `src/forex_bot/adapters/ctrader/forward_test_engine.py:515`:
```python
self._strategy_last_eval: dict[str, float] = {s.name: 0.0 for s in strategies}
```
Health monitor at `:3230-3238`:
```python
last_eval_ago = time.monotonic() - self._strategy_last_eval.get(sname, 0)
```
At process start `time.monotonic()` returns seconds since machine boot. With seed `0.0`, `last_eval_ago ≈ uptime_since_boot` (observed 1151359s ≈ 13.3d). After the first eval (line 2547) the seed becomes accurate, but the FIRST health tick after startup is bogus.

**Consumers to verify unchanged:**
- S1 health log line at `:3234` — `last=%.0fs ago` (formatted via `last_eval_ago`)
- `last_eval_ago_sec` state field at `:3652-3653` — `round(time.monotonic() - self._strategy_last_eval.get(sname, 0), 1)`

Both call `time.monotonic() - self._strategy_last_eval.get(sname, X)`. If we seed with `time.monotonic()` instead of `0.0`, the value is `monotonic() - monotonic() = 0` on the first read — correct, with units unchanged.

### Watchdog gap — **Category: missing detection / state error**

Existing detection at `forward_test_engine.py:3145-3185` only fires when `total_bars == 0` (within startup-grace). The card requires "ticks-flow-but-bars-static ≥20 min" with explicit tick-gate (no false positives on M15 boundaries).

`_update_current_bar` increments `self._health.bars_built` at `:1186` when a bar finalizes — this is the natural "bars-static" detector source. The heartbeat JSON (`:2892-2940`) does not carry any `tps` or `bars_static_*` field, so `scripts/daily_audit.py:185-209` (SH-002 `_ch_tick_flow`) reads `None → 0.0 → CRITICAL silent` regardless of actual throughput.

## Analysis

### Why the writer silence wasn't caught earlier

- The writer API is correctly used in non-blend mode and live mode — unit tests in `tests/strategies/test_signal_stats.py` exercise it directly.
- The blend mode path was added later (commit `bb4cd32 fix: record rejected orders in signal stats + fix TestCloseTrade lot_size units`) and was wired only for rejections, not opens. The early pipeline was "PaperTrader-first" but blend mode replaced that with "orchestrator-first," and the stats recorder was never re-routed.
- The "Aug 18 10:30:36 last write" timestamp corresponds to the `rejected/timeout_awaiting_event` line — the rejection was recorded from a different code path (`_execute_signal_live` reject branch at `:1781`) that was running on the previous process before blend mode took over. The 22h+ silence is the canonical signature of "writer dropped from the call graph."

### Why last= is wrong but doesn't break the world

`last_eval_ago` is purely diagnostic. Operators eyeballing S1 health lines see `last=1151359s ago` and might restart the engine "to fix it," but no automated gating depends on the value. Still: 13.3d phantom is misleading and hides the true freshness signal.

### Why SH-002 reports silent even when ticks flow

`scripts/daily_audit.py:188-189`:
```python
tps = hb.get("tps_5min_avg") or hb.get("tps_recent") or hb.get("tps") or 0.0
```
The heartbeat dict in `forward_test_engine.py:2892-2940` has none of these keys. `_health.ticks_per_second` is computed correctly (`:1243`) but never published to the heartbeat. SH-002's read is therefore permanently silent — a watchdog reading its own heartbeat and reporting that the heartbeat shows zero throughput.

## Fix Strategy

### Scope

- 3 commits, 1 branch (`autodev/sigstats-dcc7817d`).
- Files: `src/forex_bot/forward_test/blend_runner.py`, `src/forex_bot/adapters/ctrader/forward_test_engine.py`, `src/forex_bot/signal_engine/signal_stats.py` (test-only), `tests/unit/test_blend_runner_signal_id_contract.py` or new test file, `tests/strategies/test_signal_stats.py` (extend).
- ≤4 modified files per commit, total 3 commits.

### Approach

#### Commit 1: Writer silence (structural fix)
- Add `_stats_recorder: SignalStatsRecorder | None = None` to `BlendForwardTestRunner.__init__`.
- Lazy-init via `_get_stats_recorder(log_path)` property (default `data/signal_stats.jsonl`, override via config or `STATS_LOG_PATH` env var).
- In `BlendForwardTestRunner.on_signal()` (`:376`), after `order = self._orchestrator.process_signal(signal)`:
  - For accepted orders: call `record_signal(SignalRecord(...))` with `signal_id = make_signal_id(signal)`.
  - For rejected orders: call `record_rejection(...)` (mirrors the rejection-flow already wired in `_execute_signal_live`).
- In `BlendForwardTestRunner.on_fill()` (`:466`), after `self._sizer.close(order_id, pnl)`: call `record_outcome(signal_id, outcome, pips, time_to_close)` mapped from pnl sign.
- Failures are non-fatal — wrap in `try/except` + `logger.warning`.

#### Commit 2: `last=` epoch init fix
- Capture `self._strategy_init_monotonic = time.monotonic()` at engine `__init__` (alongside the existing `_last_evaluation_at = 0.0` at `:456`).
- Change `:515` to `self._strategy_last_eval = {s.name: self._strategy_init_monotonic for s in strategies}`.
- Document the seed invariant in a comment block.
- Verify consumers `:3234` and `:3652` are unchanged (they read `.get(sname, 0)` — value type stays `float`, units stay `seconds`).
- No new test required for unit semantics; one regression test confirms `last_eval_ago < bar_interval` (e.g. <900s for M15) on a fresh engine instance before any eval.

#### Commit 3: Health alert (ticks-flow-but-bars-static ≥20 min, separate commit)
- Add `self._last_bar_built_at: float = self._strategy_init_monotonic` to engine `__init__`.
- In `_update_current_bar` (`:1186` site where `bars_built += 1`): update `self._last_bar_built_at = time.monotonic()` and `self._ticks_at_last_bar_built = self._health.ticks_received` under `self._lock`.
- In `_health_monitor_loop` (`:3145` block), add detection:
  ```python
  bar_age = now - self._last_bar_built_at
  ticks_growing = self._health.ticks_received > self._ticks_at_last_bar_built
  if bar_age >= 1200 and ticks_growing and uptime > 1200 and total_bars > 0:
      logger.warning("[B5 Pipeline] BARS STATIC: %d ticks since last bar, age=%.0fs, last_bar_at=%.0f", ticks_since, bar_age, self._last_bar_built_at)
      # Rate-limit same 300s window.
  ```
- Add to heartbeat JSON (`:2892-2940`) the fields:
  - `tps_recent`: round(health.ticks_per_second, 2)
  - `tps_5min_avg`: round(health.ticks_per_second, 2) — same value (instantaneous; 5-min window would require rolling buffer; minimum viable surface is `tps_recent` so SH-002 picks it up via its `or` chain)
  - `bars_static_sec`: round(bar_age, 1)
  - `ticks_since_last_bar`: int
- Threshold: 1200s (20 min) per Satsuki's M15-boundary correction. Inside startup grace (first 1200s of uptime), the detector stays silent.

### Alternatives considered

- **Re-route via `cTraderSignalAdapter.evaluate_and_trade` to call `paper_trader.process_signal` in blend mode:** rejected — would couple blend mode to the paper-trader chain and break the "blend runner handles execution" design contract.
- **Move `SignalStatsRecorder` into `SignalOrchestrator`:** rejected — orchestrator is a pure pipeline (confidence → routing → sizing) with no I/O. Adding a JSONL write there violates separation of concerns.
- **Wire stats via `_on_trade_executed` callback in `BlendForwardTestEngine`:** considered — but the open line would land AFTER the trade is already executed, not at signal-time. Less faithful to the existing pattern.
- **Make `tps_5min_avg` a true 5-min rolling average:** considered for Fix #3 — adds rolling buffer machinery that is out of scope for a SEV-2 watch-dog-bridge fix. SH-002's `or`-chain accepts `tps_recent` as a substitute; we ship that.
